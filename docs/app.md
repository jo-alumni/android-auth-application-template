# 本アプリの目的
- 学習目的のアプリケーション
- 一般的によくある認証機能がついたアプリケーションのナビゲーション構築が主な目的

# 機能について
- 認証機能が存在する
  - すでに認証が済んでいる場合は認証画面を飛ばしてホーム画面からアプリがスタートする
  - 認証状態が確定するまではスプラッシュを維持するため、起動時は
    「スプラッシュ → ホーム/ログイン」と直接切り替わり、中間のローディング画面は見えない
    (詳しくは docs/auth-navigation.md)
  - 認証状態(トークン)は Proto DataStore に Tink の AEAD(AES256_GCM)で暗号化して永続化される
    - 暗号化鍵(keyset)自体も Android Keystore で保護されたマスターキーで包んで別ファイルに保存する
    - 復号やパースに失敗した場合は未ログイン状態にフォールバックする
  - ログイン画面はID/パスワードの入力フォームを持つ
    - ID欄からパスワード欄へIME操作(次へ)でフォーカス移動でき、パスワード欄は伏字表示・IME操作で入力を確定する
    - ID欄・パスワード欄ともオートフィル(自動入力)に対応する
    - 未入力のまま送信するとエラー表示になる(実際に通信する認証バックエンドは無く、
      入力が埋まっていれば常にダミートークンでログインに成功する)
  - ログアウト機能が存在する
    - ホーム/検索/お気に入り画面共通のTopAppBarにある「ログアウト」ボタンから実行できる
    - ログアウトすると認証状態のみ解除され、アプリデータ(DataStore等)は削除されない
  - トークンが失効した場合(サーバ側での失効・有効期限切れ)も自動的にログイン画面へ戻る
    - ログアウト操作と同じ経路(認証状態の変化)で遷移する(詳しくは docs/auth-navigation.md)
    - ログイン画面へ戻ると認証後の画面はバックスタックに残らず、
      タブごとに保存されていた状態も破棄されるため、再ログインはホーム画面から始まる
    - 動作確認用に、TopAppBarのデバッグメニュー(工具アイコン)の「トークンを失効させる」から
      手動で失効を起こせる
- 認証以外の機能
  - ボトムバー(画面幅によってはNavigationRail・常設ドロワー)で遷移可能な画面
    - ホーム画面
    - 検索画面
    - お気に入り画面
  - 詳細画面
    - 一覧の各アイテムから遷移できるほか、`authapplication://detail/{itemId}` 形式の
      ディープリンクからも直接開ける
  - 通知画面
    - ホーム/検索/お気に入り画面共通のTopAppBarにあるベルアイコンから遷移する
    - 画面全体を覆うダイアログ(全画面ダイアログ)として表示され、閉じるボタンで前の画面へ戻る
- 画面遷移アニメーション
  - ボトムバーのタブ切り替えなど同じ階層内の画面切り替えはフェードイン/フェードアウトする
  - 詳細画面のように階層を掘り下げる遷移は、遷移先が右からスライドインしながらフェードインし、
    戻る際は右へスライドアウトしながらフェードアウトする
- お気に入り機能
  - ホーム/検索/お気に入りの一覧アイテムからお気に入り登録・解除ができる
  - お気に入りはDataStoreに永続化され、アプリを再起動しても保持される
  - ある画面でお気に入りを更新すると、他の画面の一覧にも即座に反映される
- エラー表示とリトライ
  - データの取得に失敗した画面(ホーム/検索/お気に入り/詳細/通知)はエラーメッセージと
    「再読み込み」ボタンを表示し、押すと取得をやり直す
  - お気に入りの更新に失敗した場合は一覧の表示を保ったまま、Snackbarでエラーを通知する
  - 動作確認用に、TopAppBarのデバッグメニュー(工具アイコン)の「エラーを発生させる」スイッチで
    リポジトリ層に意図的に例外を発生させられる(この設定は永続化されず、再起動すると無効に戻る)

- 画面サイズへの対応
  - ナビゲーションUIはウィンドウの幅(WindowSizeClass)で切り替わる
    - Compact(幅600dp未満・一般的なスマートフォンの縦持ち): 画面下部のボトムバー
    - Medium(幅600dp以上840dp未満・小型タブレットやスマートフォンの横持ち): 画面左端のNavigationRail
    - Expanded(幅840dp以上・タブレットなど): 画面左端の常設ドロワー
  - どのUIでも遷移先・タブの選択状態・各タブのバックスタックの扱いは同じ
  - Compactのボトムバーは、一覧のスクロールに追従して隠れる/再表示される
    (下スクロールで隠れ、上スクロールで戻る。タブ切り替え時は表示状態にリセットされる)

# 実装初期のUIについて
- 最低限画面遷移に必要なUIのみで良い（ボタン押下で遷移できる、ボタンに遷移先画面名が存在するなど）

# module構成
- :app (アプリケーション本体 MainActivityなど)
- :app:core: (feature全体などで利用するような汎用的な機能)
- :app:feature:* （画面毎の機能。login/home/search/favorite/detail/notification の6モジュール）
- :domain (domain層）
- :data (data層)
